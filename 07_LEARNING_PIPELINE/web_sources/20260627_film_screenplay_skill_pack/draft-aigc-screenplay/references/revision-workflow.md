# 结构修改流程

## 修改输入

只接受用户确认的已采纳修改：

```text
修改 ID：
问题位置：
证据：
修改目标：
允许方案：
禁止改变：
```

## 执行顺序

1. 确认最早受影响场次；
2. 标记直接影响和连锁影响；
3. 重写最小充分范围；
4. 检查人物知识、关系、道具和伤势；
5. 检查后续伏笔与回收；
6. 更新版本和连续性；
7. 将未解决问题交回诊断。

## 修改类型

### 局部修改

只改变一场内的动作、信息顺序或场景目标，不改变后续主线。

### 连锁修改

改变关键事实、人物决定或场次结果，需要同步多个后续场次。

### 上游修改

涉及主题、结局、主要人物弧光或世界规则。停止执行，退回 `develop-aigc-screenplay`。

## 防止越改越大

- 不顺便优化未列入清单的场次；
- 不把个人偏好伪装成诊断共识；
- 发现新问题先登记，不在同一轮无限扩张；
- 修改完成后推荐重新诊断受影响范围。
