# Extracted Rules - Bilibili AI人物真实表情精确控制

- 来源：https://www.bilibili.com/video/BV183KS66EeZ/
- 状态：用户确认此次外部资料完全有用；可迁移结论已进入 `i2v-prompt-workflow` Skill。未直接写入 `01_ACTIVE_RULES/`。
- 适用范围：AIGC 短剧、I2V 分镜提示词、Seedance 2.0 全能参考工作流中的人物表演层。

## 1. 抽象情绪必须翻译成可见脸部部位

### 原始观点

视频明确反对只写“生气、开心、嘲讽、惊讶”等笼统情绪词，建议拆成：

- 眉毛
- 眼睛 / 眼神
- 嘴巴 / 嘴角
- 面部肌肉

### 可迁移规则

正式提示词中，如果镜头承担情绪表达功能，应把核心情绪改写成可见表演。

```text
不要只写：他愤怒地看着对方。
建议写：他眉毛紧皱下压，眉心挤出川字纹，眼神死死压住对方，嘴唇紧抿，牙关绷紧，面部肌肉僵硬。
```

### 使用边界

这个拆解只适合近景、中近景、特写、反应镜头、情绪转折镜头。远景或快速动作镜头中，优先写身体动作和整体姿态，不要堆细小脸部变化。

## 2. 表情必须绑定动作、台词和当前剧情触发点

### 原始观点

视频强调“表情永远和动作台词绑定”。例如放狠话配合咬牙，嘲讽配合嘴角斜挑，正经说话配合嘴巴微张。

### 可迁移规则

表情不是独立装饰，应回答三个问题：

- 角色正在做什么？
- 角色刚刚听到或看到什么？
- 角色为什么在这一秒出现这个表情？

```text
前置信息：他刚发现盟友把军令卖给敌营。
镜头表情：他先维持平静，听到对方说出暗号时，瞳孔瞬间收缩，嘴角轻轻压下，握笔的手停住半秒，随后恢复冷静。
```

这与用户已有测试结论一致：连续性信息不是全局流水账，而是服务当前片段表演的前置解释。

## 3. 景别决定表情颗粒度

### 原始观点

视频提出“不同景别表情幅度不一样”：远景、全景需要更大表情或身体动作；近景、特写需要更细腻的表情肌肉、皮肤纹理和眼神变化。

### 可迁移规则

写提示词前先判断镜头景别：

- 远景 / 全景：写大动作、姿态、停顿、后退、握拳、转身、垂头。
- 中景 / 中近景：写眼神方向、眉头、嘴角、呼吸、肩颈变化。
- 近景 / 特写：可以写瞳孔、眼尾、唇线、咬肌、面部细纹、青筋、泪光。

### 风险

如果在远景中写“瞳孔收缩、嘴角细微抽动”，模型大概率无法稳定呈现；如果在特写中只写“很愤怒”，表演又会显得粗糙。

## 4. 微表情应写成短暂动态过程

### 原始观点

视频的微表情模板包含：

- 初始表情状态
- 触发事件
- 某个部位的细微变化
- 立刻恢复原状态
- 变化极快，不易察觉

### 可迁移规则

微表情不是“更夸张的表情”，而是短暂泄露真实心理的瞬间。

```text
表情变化：他原本平静地低头看文书；听到“北门已开”时，眼神微微一滞，瞳孔瞬间收缩，嘴角极轻地压了一下；随即恢复平静，继续翻页，变化极快，不易察觉。
```

### 使用边界

微表情适合：

- 角色隐瞒真实动机
- 谎言被戳中
- 关系反转
- 战前对峙
- 爱恨、恐惧、羞耻、杀意等不能直接外露的瞬间

不适合：

- 普通过场镜头
- 快速打斗主动作镜头
- 大远景调度
- 已经需要强烈外放表演的崩溃戏

## 5. 多人场景需要表情主次

### 原始观点

视频强调多人场景不能只有说话主角有表情，否则配角像木头人；但也不能所有人同等详细。

### 可迁移规则

多人镜头表情层级：

- 主角：表情精细，承担画面焦点。
- 对手：表情与主角形成反差，情绪强度匹配。
- 配角：符合人设，适当简化，必要时虚化，不抢主体。
- 背景人物：只写群体情绪或姿态即可。

```text
表情主次：沈砚保持温和笑意，眼神却压低，像在诱导；陆直盯着纸面，眉心收紧，嘴唇抿住；旁边书记员低头避开视线，只露出紧张的侧脸，不抢主体。
```

## 6. 表情提示不应每镜头硬套四部位

### 规则

视频提供的拆解方法有价值，但在仓库最终 Skill 中应作为“按需启用”的表演层，而不是每个镜头的固定必填项。

建议判断顺序：

1. 这个镜头是否承担情绪变化？
2. 是否有近景、特写、反应镜头？
3. 是否存在当前片段前置信息或触发事件？
4. 是否需要微表情，而不是外放表情？
5. 是否为多人镜头，需要主次表情？

只有判断为“需要”时，才展开眉毛、眼神、嘴部、面部肌肉。

## 7. 不吸收外部平台绑定格式

### 原始素材中的格式

视频模板大量使用：

```text
@1 场景参考
@2 人物名称
@3 主角
```

并反复出现“UE5建模风格、LibTV、电影质感”等外部风格词。

### 仓库处理方式

这些不应进入最终正式提示词 Skill：

- Codex 不替用户写 `@` 资产绑定。
- 不默认写外部平台名称。
- 不用风格堆叠替代表演设计。
- 只吸收“表情拆解逻辑”和“镜头判断逻辑”。

## 建议升级为正式 Skill 的候选块

### 表情层判断

```text
写正式提示词前，先判断当前镜头是否需要精细表情：
- 如果是近景、特写、反应镜头、情绪转折、高光对峙，则展开表情层。
- 如果是远景、动作调度、普通过场，则只写整体情绪、姿态或身体反应。
```

### 单人物表情写法

```text
表情：眉毛...；眼神...；嘴部...；面部肌肉...；整体情绪...
```

### 微表情写法

```text
表情变化：人物原本保持...；听到/看到...时，眼神/眉毛/嘴角微微...；随即恢复...；变化极快，不易察觉。
```

### 多人表情写法

```text
表情主次：主角表情精细突出；对手表情形成反差；配角符合人设但简化处理，不抢主体。
```
