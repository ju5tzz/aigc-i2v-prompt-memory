# Film Screenplay Skill Pack 逐项分析

## 来源

- 入库位置：`07_LEARNING_PIPELINE/web_sources/20260627_film_screenplay_skill_pack/`

本文件结合该 Skill 包内容和本仓库现有 I2V 规则进行分析。所有结论均为外部经验判断，不代表已通过本仓库项目实测。

## 总体判断

这个包比单个视频提示词 Skill 更有价值，因为它关注的是上游影视生产链：故事开发、诊断、初稿、台词、资产圣经、连续性账本、分镜交接、Seedance 执行。

它对本仓库的潜在增量主要不在“怎么写一个更好的 I2V 提示词”，而在“如何让一个项目从剧本阶段就为 AIGC 生产做好状态管理”。这能补强目前仓库偏 I2V 执行层的内容。

最有吸收价值的部分：

- 项目状态包：统一记录阶段锁定状态、故事核心、人物关系、资产、连续性、诊断问题、已采纳修改、生产风险。
- 资产圣经：用稳定 ID 管理角色、场景、道具、车辆、视效和声音资产。
- 连续性状态账本：记录人物知道的信息、误解、关系、伤势、服装、道具、场景破坏、伏笔和倒计时。
- 分镜交接单：把剧本信息转成下游分镜/I2V 可以执行的交接字段。
- AIGC 可生产性诊断：区分“保留并攻克”“保留功能但调整表现”“重写场景”。
- 对白口型与声音可执行性：把对白精修和 I2V 口型、声音来源、片段时长联系起来。

## 逐项判断

### 1. `develop-aigc-screenplay`

定位：AIGC 剧本工作流主控，负责故事开发、人物主题、资产圣经、连续性、生产风险、阶段门禁和分镜交接。

有价值内容：

- “故事优先 + 生产轨并行”的双轨评价：不能为了降低 AIGC 生产难度削弱故事高潮、主题或人物选择。
- 项目状态包：把故事核心、人物、资产、连续性、诊断问题、台词声纹、AIGC 生产诊断放进统一状态。
- 资产圣经：明确 `CHR / ENV / SET / PROP / EQP / VEH / VFX / SND` 等资产类别。
- 连续性状态账本：从剧本阶段记录人物状态、场景状态、道具状态和叙事信息状态。
- 分镜交接契约：把剧本交给下游分镜前，明确不可删除信息、起止状态、空间方向、生成风险、允许调整与禁止改变。

与本仓库关系：

- 高度兼容。它能补强本仓库目前较少覆盖的“剧本到 I2V 之前的项目状态层”。
- 与 `04_ASSET_RESPONSIBILITIES.md` 互补：现有仓库说明资产职责，这个 Skill 说明资产如何从剧本阶段建档。

风险：

- 流程很重，不适合每次小镜头任务。
- 如果直接照搬，可能把创作过程变成表格负担。

建议：

- 高优先级吸收“项目状态包、资产圣经、连续性账本、分镜交接单”。
- 不直接照搬完整 Skill，只提炼为轻量模板。

### 2. `diagnose-aigc-screenplay`

定位：对剧本、大纲、场次、段落做证据化诊断，不直接重写。

有价值内容：

- 明确诊断 Skill 不直接重写，先输出问题单，由用户采纳后再交给重写 Skill。
- 诊断对象包括故事、人物、节奏、观众理解、原创性和 AIGC 生产风险。
- 问题单要求引用具体场次、动作或台词作为证据。

与本仓库关系：

- 兼容外部经验“先诊断再修改”的原则。
- 可补强当前反馈记忆：失败不是直接改 prompt，而是先标记问题类型和证据。

风险：

- 诊断层和修改层分离会增加交互轮次。
- 对极短 I2V 镜头可能过重。

建议：

- 吸收“证据化问题单”和“用户采纳后再改”的机制。
- 用在剧本片段、分镜、连续失败镜头，不作为所有提示词任务默认步骤。

### 3. `draft-aigc-screenplay`

定位：把已锁定故事核心、人物和分场扩写成剧本，或执行已采纳问题清单。

有价值内容：

- 只执行已锁定或已采纳内容，不重新设计故事前提、主题、结局和人物弧光。
- 修改时更新连续性变化、资产疑点和版本记录。
- AIGC 写作规则强调可见、可听、可执行的动作因果。

与本仓库关系：

- 与现有“模型只执行可见/可听/空间/动作/声音”原则一致。
- 对将来做 AI 短剧剧本到分镜的流水线有用。

风险：

- 对仓库当前核心的 I2V 提示词层提升有限。
- 如果没有项目状态包，它的价值会下降。

建议：

- 作为上游剧本生产流程参考保留。
- 不直接进入 I2V active rules。

### 4. `polish-screenplay-dialogue`

定位：结构锁定后精修台词，关注人物声纹、潜台词、冲突、信息效率、口型、发音和片段长度。

有价值内容：

- 台词精修不改变剧情结构、主题、结局或人物弧光。
- 建立角色语言指纹：词汇、句长、句式、停顿、潜台词策略、禁用表达。
- 把对白长度、口型、声音来源和视频片段切分联系起来。

与本仓库关系：

- 与声音/对白提示词规则高度相关。
- 可补强当前仓库对“中文对白字数、语速、口型压力”的管理。

风险：

- 如果过度精修台词，可能牺牲短剧节奏和视频可执行性。
- 对无对白镜头价值较低。

建议：

- 高优先级提炼“对白声纹 + 口型长度检查”。
- 后续可作为 `05_FEEDBACK_MEMORY` 或 `02_TEMPLATES` 的候选补充，但需实测。

### 5. `five-dimension-storyboard`

定位：把剧本、场景、大纲或对白转成五维度影视分镜表或可复制镜头提示词，是 Seedance 下游提示词之前的上游分镜。

有价值内容：

- 默认“跑视频保真模式”：保留剧本信息，不随意总结掉关键动作、关系和视觉细节。
- 三个镜头视角：导演、动作、分镜。
- 按脚本类型判断分镜策略：对峙、动作、独白、追逐、亲密、群戏、闪回、大场面等。
- 15 秒内分段，密集对白或动作可拆得更短。
- 把标点视为表演和声音方向，保留原对白并在外部添加表演说明。

与本仓库关系：

- 与现有故事板和 I2V 分段规则高度兼容。
- 对“剧本到分镜”的中间层有较强补充。

风险：

- 可能输出较长、偏人类阅读的分镜表，进入 I2V prompt 前仍需压缩。
- “保真”会增加提示词密度，需要与模型执行能力平衡。

建议：

- 吸收“跑视频保真模式”和“标点/停顿作为表演”的思路。
- 不把五维表格作为默认 I2V 输出格式。

### 6. `qingdaofu-storyboard`

定位：清道夫分镜，强调资产锁定、摄影参数、画面调度、人物表演、声音设计、时间预算和物理约束。

有价值内容：

- 分镜不是摆位，而是“情绪如何发生”。
- 用微表演替代抽象情绪词：眼神、呼吸、指节、喉结、肩线、嘴角。
- 环境参与：风、光、尘、衣料、道具、空间压迫参与戏剧表达。
- 时间预算表：目标生成时长、有效叙事时长、预算拍数、实际拍数、对白字数、风险结论。
- 竖屏构图规则：主体面部和手部优先、前景遮挡和空间层次、避免多人横向排开。

与本仓库关系：

- 与现有微表情、声音、9:16、时间切片规则高度兼容。
- 真正有增量的是“时间预算表”和“环境参与”。

风险：

- 清道夫模板很重，直接用于所有片段会使提示词臃肿。
- 它倾向把很多内容放入单条“投喂提示词”，而本仓库更强调 prompt 层与参考层隔离。

建议：

- 吸收：微表演、环境参与、时间预算。
- 暂不吸收完整清道夫五段模板。

### 7. `seedance-shot-prompt`

定位：把上游分镜转成 Seedance 2.0 可执行提示词，并诊断角色一致性、首帧/尾帧、参考图/视频/音频等。

有价值内容：

- 第一步识别输入模式：文生视频、首帧图生视频、首尾帧、Omni Reference、视频参考、音频参考。
- 参考素材角色表：不同图片/视频/音频分别承担身份、场景、道具、风格、首帧、尾帧、运动或声音角色。
- 首帧权重高于普通参考图；首尾帧模式要求运动因果连接。
- 输出执行风险：身份漂移、构图冲突、对白过长、动作过密等。
- 压缩优先级：先删风格堆叠，再删环境冗余，保留参考角色、动作节拍、台词和尾帧。

与本仓库关系：

- 高度相关，但存在一个明确冲突：该 Skill 允许使用实际 `@image1` / `@video1` / `@audio1` 等平台引用；本仓库当前规则要求 Codex 默认只输出提示词层，不直接写平台资产绑定。
- 参考素材“角色表”本身非常有价值，但应作为用户手动绑定前的说明层，而不是默认进入最终 prompt 正文。

风险：

- 直接吸收会破坏“提示词层 / 参考层分离”原则。
- 不同平台 UI 和资产引用格式变化快，直接写平台 ID 容易过时。

建议：

- 吸收“参考素材角色表”和“输入模式判断”。
- 不吸收默认 `@image` 写入最终提示词正文的做法。

### 8. `ap-aigc-prompt`

定位：生成 Seedance 与 GPT-Image-2 生产级 AIGC 视频分镜/提示词，包含资产提取、角色参考图、关键帧、首尾帧、遮罩转场和提示词清理。

有价值内容：

- 先做资产提取，再设计镜头：角色/生物、场景、道具装备、VFX、音频、连续性状态。
- 把隐喻、IP 参考、情绪和抽象词翻译成可见的摄影机行为。
- 区分 Seedance 视频提示词与 GPT-Image-2 关键帧/角色图提示词。
- 包含首尾帧、状态变化、遮罩转场、多段连续性等生产级概念。

与本仓库关系：

- 资产提取、抽象词转可见行为，与仓库高度兼容。
- GPT-Image-2 关键帧和遮罩转场部分属于更宽的 AIGC 生产流程，可作为辅助来源，不直接进入 I2V 主规则。

风险：

- 工具和模型名更新较快，具体模型规则需谨慎。
- “最终写实际 .txt 文件”的交付方式不一定适合当前仓库每次任务。

建议：

- 吸收“资产提取先于镜头设计”和“抽象参考转可见行为”。
- GPT-Image-2 与遮罩转场内容暂存为外部来源，等真实项目需要时再测试。

## 与本仓库现有规则的关系

### 已经趋同的内容

- 提示词必须写可见、可听、可执行内容。
- 单段 Seedance / I2V 通常控制在 4-15 秒。
- 资产、角色、场景、道具、声音应分层管理。
- 分镜要写机位、景别、动作、声音、结束状态。
- 抽象情绪要转成微表演、动作和环境变化。
- 参考素材不能含糊地“什么都管”，必须有明确职责。

### 对仓库有实质补强的内容

- 项目状态包。
- 资产圣经。
- 连续性状态账本。
- 分镜交接单。
- AIGC 可生产性诊断。
- 台词声纹与口型/字数检查。
- 参考素材角色表。
- 时间预算表。
- 环境参与机制。

### 需要保留冲突或暂不吸收的内容

- 默认把 `@image1`、`@video1`、`@audio1` 写入最终提示词正文。
- 对所有任务强制完整上游剧本流程。
- 过重的清道夫五段模板。
- 与具体模型或工具绑定过深的规则。
- 默认生成 `.txt` 文件作为交付方式。

## 入库建议

该包应作为“上游影视生产工作流”来源归档。下一步更值得做的不是继续吸收完整 Skill，而是从中拆出 4 个可测试的小模板：

1. AIGC 项目状态包模板。
2. I2V 资产圣经模板。
3. 连续性状态账本模板。
4. 分镜交接单模板。

这些模板如果经真实项目验证有效，再考虑进入 `02_TEMPLATES/`；在验证前，只保留在 `07_LEARNING_PIPELINE/`。
