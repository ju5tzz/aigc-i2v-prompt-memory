# Diagnose AIGC Screenplay

## 定位与职责边界（Boundary）

对剧本、大纲、序列或单场进行证据化诊断，形成可供用户选择的问题单。

负责：

- 识别故事、人物、场次、观众理解、制作和 AIGC 生产问题；
- 引用具体场次、动作或台词作为证据；
- 说明影响、优先级、修改目标、可选方向和可能损失；
- 标记值得保留的设计；
- 更新项目状态包中的诊断问题单和版本记录。

### 禁止直接重写（No Direct Rewrite）

本 Skill 不直接重写剧本，不替用户做最终取舍，也不逐句精修台词。

用户采纳问题后，交给 `draft-aigc-screenplay` 执行；结构锁定后的台词问题交给 `polish-screenplay-dialogue`。

## 共享项目状态包（Shared Project State）

优先读取 `develop-aigc-screenplay` 生成的项目状态包。没有状态包时，可从材料反推简要上下文，但所有推断标记为 `【合理推断】`。

本 Skill 只写：

- 诊断问题单；
- 建议保留清单；
- 版本变更记录；
- 职责外变更请求。

不修改正式剧本、人物圣经、分场表或连续性账本。

## 诊断门禁（Gate）

- 只有一句创意：不做全剧诊断，建议先开发故事；
- 只有大纲：可以诊断结构，但不得假装评判表演和逐句台词；
- 单场片段：只诊断本场及已提供的上下文；
- 没有作品形态或目标时长：先做最小必要确认；
- 用户要求“直接帮我改”：先输出问题单，待用户采纳后路由至 `draft-aigc-screenplay`。

## 四个稳定诊断面

完整框架读取 `references/diagnostic-framework.md`。

### 1. 编剧诊断

关注：

- 故事前提；
- 人物目标与主动性；
- 因果和冲突升级；
- 场景功能；
- 高潮选择；
- 主题兑现。

### 2. 观众诊断

关注：

- 开场承诺；
- 信息是否看得懂；
- 情绪是否能进入；
- 类型体验是否兑现；
- 结尾是否值得记住；
- 是否存在无效等待或重复。

### 3. 制作诊断

关注：

- 场景、角色和资产规模；
- 演员表演压力；
- 动作、视效和声音难点；
- 预算或制作复杂度；
- 原创性、IP 和合规风险。

### 4. AIGC 生产诊断

关注：

- 角色身份稳定；
- 多主体同框；
- 手部和道具交互；
- 空间方向；
- 伤势、服装和环境连续性；
- 口型与长对白；
- 动物、异形、液体、镜面、破坏和高密度视效；
- 下游需要专项测试的场次。

## 证据契约（Evidence Contract）

每个问题必须包含：

```text
问题 ID：
问题位置：
引用证据：
诊断维度：
为什么是问题：
影响：
优先级：
修改目标：
可选方向：
可能损失：
建议负责 Skill：
```

禁止：

- “节奏不好”“人物不够立体”等无证据判断；
- 为满足数量硬凑问题；
- 用虚构评委履历为意见背书；
- 把个人偏好写成必须修改；
- 直接输出重写后的整场戏。

## 优先级

### 必改

问题阻断故事理解、人物因果、高潮成立、核心连续性或生产执行。

### 建议改

存在明确收益，但不改仍能成立。

### 可议

取决于作者目标，需说明不同选择的收益与损失。

### 建议保留

已有效承担故事、人物、情绪或生产功能，不应因修改其他部分被误伤。

优先级来自影响，不来自“有几位虚构评委同意”。

## 诊断流程

1. 确认诊断范围和用户身份；
2. 建立事实清单，不先下判断；
3. 按四个诊断面扫描；
4. 合并指向同一根因的问题；
5. 输出问题单和建议保留清单；
6. 要求用户选择采纳项；
7. 将采纳项写入项目状态包，路由至 `draft-aigc-screenplay`。

## 台词边界

可以指出：

- 大量解释性对白；
- 人物语言无法区分；
- 对白破坏场景冲突；
- 口型和长度造成生产压力。

不进行逐句改写。结构锁定后移交 `polish-screenplay-dialogue`。

## 输出

使用 `assets/issue-register-template.txt`。

输出最少包括：

- 范围与材料限制；
- 问题单；
- 建议保留；
- 分歧或取舍；
- 用户必须做的下一项决定；
- 下一步负责 Skill。

## 常见错误

- 诊断和改写混在同一轮；
- 大纲诊断假装看到了完整表演；
- 四个视角重复同一个批评；
- 只谈市场，不谈故事证据；
- 生产风险被当成删除场景的理由；
- 用户尚未采纳，就把所有建议交给重写。
