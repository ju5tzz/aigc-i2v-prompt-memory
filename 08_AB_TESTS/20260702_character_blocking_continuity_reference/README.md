# 多人物站位连续性参考图测试

> 建立日期：2026-07-02
> 当前状态：待真实 I2V 生成验证
> 适用范围：Seedance / I2V 短剧，全能参考工作流，多人物站位连续性

## 测试目的

本文件夹用于记录“短剧片段之间的人物站位连续性”测试。

在当前全能参考工作流中，人物设定图解决“角色是谁”，空场景图解决“人物在哪个环境中”，但 3 人及以上场景仍然容易出现一个核心问题：上一个片段结束时的人物站位，无法稳定继承到下一个片段，导致人物漂移、左右互换、前后景错乱、无动作角色被重置，或者镜头切换后空间关系崩掉。

提示词可以描述站位，但模型通常更吃图片参考里的位置信息。因此本测试的目标不是继续堆长文字，而是寻找一种高效、可复用、足够准确的“站位参考图”方法，让下一段视频能继承上一段的角色位置、远近关系、面朝方向和主次关系。

本目录中的内容全部属于测试假设。未经多轮真实生成验证前，不进入 `01_ACTIVE_RULES/`，也不写入正式 `i2v-prompt-workflow` Skill。

## 两条生产思路

### 思路 A：提前系统性设计站位参考图

先把一集短剧拆成若干个低于 15 秒的生成片段，再根据剧情为每个片段设计起始站位、结束站位，以及下一段需要继承的站位参考图。

优点：

- 最理想、最可控。
- 同一个场景内可以连续生产，不必等上一段生成完再开始下一段。
- 可以提前规划人物远近、朝向、遮挡、画面主次和镜头调度。
- 不容易被上一段生成结果中的错误站位拖累。

缺点：

- 前期设计成本较高。
- 创作者必须预判每个片段的理想结束状态。
- 如果实际生成结果偏离计划，后续预设站位图可能和成片不一致。

### 思路 B：从上一段视频截取关键帧作为锚点

等上一个片段生成后，从结尾或接近结尾的位置截取一张有参考价值的关键帧，作为下一个片段的站位参考锚点。

优点：

- 最贴近上一段真实成片。
- 如果上一段结尾状态很好，下一段直接继承它会更自然。
- 单个续写测试的准备成本较低。

缺点：

- 同一场景内无法连续生产，必须等上一段生成完成后才能准备下一段。
- 如果上一段已经发生人物漂移、身份混淆或构图错误，下一段可能会继承错误。
- 截取帧可能存在动态模糊、人物遮挡、表情不合适、镜头角度不适合作为下一段起点等问题。

## 待测试的参考图类型

当前尚不知道哪一种参考图最有效，需要分开测试，避免一次叠加太多变量。

### 类型 1：俯视平面站位图

用俯视图标出角色位置、面朝方向和主要场景物件。

测试假设：

- 对逻辑空间关系可能有效。
- 但模型未必能稳定把俯视图转换成竖屏镜头画面。

### 类型 2：空场景图叠加彩色人物剪影

在空场景图上叠加简单彩色人形剪影或色块，用来标出每个角色的屏幕位置、远近、朝向和遮挡关系。

测试假设：

- 可能是第一优先级测试方案。
- 同时提供真实场景透视和可见画面位置。
- 剪影只承担站位信息，不承担人物身份信息，较不容易和人物设定图冲突。

### 类型 3：下一段首帧粗构图参考图

直接制作下一段开头应当出现的粗略画面。人物站在正确位置，但尽量弱化脸部和服装细节。

测试假设：

- 对视觉连续性可能最强。
- 制作成本较高。
- 如果人物细节太多，可能和人物设定图争夺身份权重。

### 类型 4：上一段结尾关键帧

直接使用上一段生成视频的结尾帧，或接近结尾的有效帧，作为下一段站位锚点。

测试假设：

- 当前一段生成结果已经很好时，继承效果可能最强。
- 当前一段存在错误时，错误会被下一段放大。
- 需要和类型 2、类型 3 在同一提示词下对比。

## 核心测试变量

每轮测试尽量只改变一个主要变量。

| 变量 | 可测范围 |
| --- | --- |
| 参考图类型 | 无站位图 / 俯视平面图 / 空场景彩色剪影 / 首帧粗构图 / 上一段关键帧 |
| 可见人数 | 先测 3 人，再测 4 人，最后测 5 人及以上 |
| 动作负担 | 静态对话 / 单人向前一步 / 两人交叉移动 / 镜头重新构图 |
| 镜头负担 | 固定竖屏中景 / 缓慢推进 / 过肩 / 反应切镜 / 手持移动 |
| 场景负担 | 空房间 / 围桌 / 门口 / 宫殿或办公室多人场景 |
| 身份负担 | 服装差异明显 / 服装接近 / 人物部分遮挡 |

## 结果评估标准

每次生成后按以下维度记录，不只看“画面好不好看”，重点看站位是否被继承。

| 维度 | 判断问题 |
| --- | --- |
| 身份稳定 | 模型是否保持谁是谁 |
| 左右连续 | 角色是否保持原本的画面左右位置 |
| 前后景连续 | 前景、中景、后景关系是否正确 |
| 面朝方向 | 角色是否面向正确的人或物 |
| 遮挡关系 | 前后遮挡是否可信 |
| 无动作角色稳定 | 没有行动的人是否留在原地 |
| 动作兼容性 | 新动作是否发生，同时不破坏站位 |
| 图文冲突 | 参考图是否压过或误导了提示词 |
| 生产成本 | 该方法是否能支撑短剧批量生产 |

## 初始测试顺序

1. 先做一版纯文字站位提示词，作为对照组。
2. 优先测试“空场景图叠加彩色人物剪影”。
3. 用同一场景和提示词测试“上一段结尾关键帧”。
4. 如果彩色剪影有效但精度不足，再测试“下一段首帧粗构图”。
5. 如果模型总是理解错空间逻辑，再补测“俯视平面站位图”是否适合作为辅助参考。

## 升级为 Skill 的条件

至少通过以下真实测试后，才能考虑把经验写入正式 Skill：

- 3 人静态对话。
- 3 人场景中，只有 1 人发生小幅移动。
- 4 人围桌或对峙场景。
- 1 次从上一段生成视频关键帧继承到下一段。
- 1 次同一场景内提前规划 3 个连续低于 15 秒片段，并保持站位连续。

在达成这些条件前，本目录只保留为测试记录和假设库，不升级为稳定规则。
