# Extracted Rules - 外部 Skill / 实战经验吸收方法

- 来源：用户对 `mx-shell-prompt` 外部 Skill 分析后的反馈
- 当前状态：待验证 / 方法论候选

这些内容用于指导如何处理外部 Skill、社区教程和创作者实战经验。它们不能直接替代 `01_ACTIVE_RULES/`，但可以作为学习管线的判断框架。

## 1. 外部经验既不全盘接收，也不武断否定

### 原始观点

获取到别人的实战工作经验后，最有效的方式不是全面接收，也不是武断否定，而是实际验证，然后有条件地吸收。

### I2V 可迁移假设

所有外部技巧都应拆成可测试变量，例如：

- 是否提高镜头稳定性。
- 是否改善画面质感。
- 是否提升动作执行。
- 是否污染提示词。
- 是否和当前工作流边界冲突。

### 建议流程

```text
外部经验 → 拆成变量 → 标注与现有规则关系 → 设计小实验 → 用户实测反馈 → 条件吸收 / 暂缓 / 排除
```

## 2. 参考层绑定是必需的，但不属于 Codex 输出的提示层

### 原始观点

外部 Skill 默认在提示词中写 `{{Portrait N}}` 或类似资产绑定。这个参考部分对平台生成是必不可少的，但它不是 Codex 当前应该输出的提示词正文。

### 当前工作流边界

Codex 输出：

```text
小明对着老师鞠了一躬。
```

用户在平台中手动补充参考层：

```text
小明@图一 对着老师@图二 鞠了一躬。
```

### 待验证点

需要继续验证“提示层是否应保留清晰人物名、角色关系、动作和视线”，但不把资产绑定写进正文。

## 3. 完整角色外貌设定是否有价值，需要按场景验证

### 原始观点

外部 Skill 会在提示词里写完整角色外貌设定。但在当前工作流中，角色外貌更多由参考资产承担。

### I2V 可迁移假设

如果角色资产已经稳定，提示词应重点写：

- 人物调度
- 动作
- 视线
- 表情变化
- 台词
- 镜头关系

完整外貌设定是否还需要写，要看具体场景验证。

### 待验证实验

同一角色镜头测试：

- 只写人物名 + 动作。
- 写人物名 + 简短身份标签 + 动作。
- 写完整外貌设定 + 动作。

比较角色一致性、提示词污染和动作执行。

## 4. 摄影机 / 镜头型号 / 风格词堆砌是否有效，需要实验

### 原始观点

外部 Skill 使用大量电影级术语、摄影机型号、镜头型号、风格参考。它可能提高视频质感，也可能只是术语堆砌。

### I2V 可迁移假设

术语只有在能够影响以下内容时才值得保留：

- 景别
- 构图
- 运镜
- 光源
- 色彩
- 材质
- 运动模糊
- 画面质感

### 待验证实验

同一镜头测试：

- 不写摄影机 / 镜头型号，只写具体画面。
- 写少量关键摄影术语。
- 写完整摄影机、镜头、胶片、导演风格词。

比较画面质感、执行稳定性和是否出现风格污染。

## 5. 负面指令集中放在风格核心，需要专门验证

### 原始观点

外部 Skill 建议把负面指令集中放在风格核心，而不是散落到每个镜头。

### 与现有规则的关系

当前正式规则强调避免大量负面词污染当前画面。外部经验与该规则存在张力。

### I2V 可迁移假设

集中负面指令可能有助于统一风格，减少重复；但长负面列表可能把不该出现的概念引入模型上下文。

### 待验证实验

同一片段测试：

- 无负面风格核心。
- 短负面风格核心。
- 长负面风格核心。
- 每镜头分散负面提示。

比较画面污染、真实感、角色稳定性和动作执行。

## 可吸收但需改造的外部 Skill 结构

可以吸收：

- 一个板块 = 一次生成单元。
- 道具单列，并写状态和与事件的关系。
- 每个镜头包含景别、构图、运镜、画面内容。
- 自动判断多分镜或一镜到底。
- 跨板块保持角色、画幅、风格一致。

必须改造：

- 删除自动资产绑定。
- 避免重复完整外貌设定。
- 避免无验证的摄影术语堆砌。
- 负面指令策略进入实验，不直接固化。
