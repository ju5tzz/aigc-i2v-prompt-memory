## 总体判断

这三个 Skill 的真正价值不在单个提示词，而在它们把 AI 短片制作拆成了三个较清楚的生产岗位：

1. 编剧岗位：把点子变成可拍摄故事，并不断诊断核心冲突。
2. 美术/资产岗位：把剧本拆成角色、场景、道具和静态资产提示词。
3. 执行导演/拍摄岗位：把剧本、资产和空间关系转成镜头列表与 Seedance 视频提示词。

这与视频中的核心观点一致：精品 AI 短片不是“一条神级提示词”产物，而是由剧本、资产、拍摄、检查、重抽组成的工作流。智能体的价值是做拆解、组织、检查和中间稿生产；人的价值仍是判断方向、取舍和审美。

对本仓库来说，最值得吸收的是工作流结构和确认机制，而不是直接照搬这三个 Skill 的输出格式。

## 三个 Skill 逐项判断

### 1. `deepwhite-screenwriting-v1`

定位：中文影视编剧与剧本医生。

主要价值：

- 强调不要一次性让 AI 写完整剧本，而是从体量、核心动作、高概念、人物弧光、世界观、结构大纲、分场、场景写作逐步推进。
- 每个正式步骤后等待用户 `通过 / 修改 / 自检`，让人保留关键判断权。
- 引入剧本医生、量化评分、因果链、人物缺陷、场景价值转变等检查机制。

与本仓库关系：

- 与仓库中“镜头服务故事、信息和情绪”的立场兼容。
- 适合作为 I2V 生产前的上游故事诊断工具。
- 不应直接进入 I2V 提示词模板，因为它处理的是剧作层，不是模型执行层。

风险：

- 流程较重，如果用户只需要改写一个 8-15 秒片段，完整编剧流程会显得拖慢。
- 输出中可能包含较多给人看的解释，需要在进入 I2V 提示词前剥离。

建议：

- 可吸收“剧本前置诊断”思想。
- 不直接采用完整 Skill 流程。
- 对短剧/I2V 任务，可改造成轻量检查：核心冲突、角色目标、障碍、反转、片段终点。

### 2. `deepwhite-image-prompt-builder`

定位：静态图像提示词生成，用于人物、场景、道具、海报、关键帧、概念图。

主要价值：

- 明确只做静态图，不写视频提示词。
- 提示词结构稳定：主体动作、地点、构图、灯光、风格、镜头/镜头语言、色彩。
- 对资产图阶段有帮助，尤其是角色设定图、场景概念图、关键道具图。

与本仓库关系：

- 与 `01_ACTIVE_RULES/04_ASSET_RESPONSIBILITIES.md` 中的资产职责划分兼容。
- 可作为“参考层资产生成”的辅助材料，但不属于 Codex 最终 I2V 提示词正文。
- 适合进入资产库生产阶段，而不是视频提示词阶段。

风险：

- 它默认输出中英双语，但本仓库目前更强调模型可执行的中文 I2V 指令；双语是否有益需要按图像工具测试。
- 它不处理资产绑定、资产职责冲突、同一角色多图一致性问题。

建议：

- 可保留作为静态资产提示词外部参考。
- 若后续改造成仓库内部 Skill，应加入“资产职责”与“一致性检查”字段。

### 3. `deepwhite-shotlist-builder-zh-user`

定位：把剧本或场景拆成中文影视分镜、Seedance 2.0 视频提示词、直接文本提示词或分镜网页。

主要价值最高。它和本仓库最接近，包含多个强工作流机制：

- 资产确认：先确认人物、场景、道具、故事板，不确认不写提示词。
- 空间确认：多人物或复杂空间先输出俯视站位关系，再确认。
- 时间划分：每条提示词最多 15 秒，不机械拆太碎。
- 提示词结构确认：允许用户先确认最终提示词字段。
- 交付格式确认：文字提示词与 HTML 网页分离。
- HTML QA：如果做网页，检查长文本换行、表格稳定性、避免 `rowspan/colspan`。

与本仓库高度兼容的部分：

- 15 秒以内的生成单元，与本仓库 `01_I2V_CORE_RULES.md` 相符。
- 强调镜头编号、动作、构图、机位、声音、结束状态，与本仓库标准 I2V 模板相符。
- 强调故事板可作为构图、动作、信息参考，不让编号、箭头、文字框进入最终画面，与本仓库故事板规则相符。
- 强调空间位置确认，可补强本仓库现有“起点、中段、终点必须保持同一空间、同一主体、同一方向”的要求。

需要警惕的部分：

- 该 Skill 的参考文件中出现 `@image` / `@image1` 风格资产引用示例；本仓库当前规则要求 Codex 只输出提示词层，不直接写 `@Image`、`@Video`、平台资产 id 或猜测绑定。
- 该 Skill 的确认门较多，适合复杂制作，但不适合所有轻量任务。若照搬，会让简单片段的交互成本过高。
- HTML 生产表很有用，但属于交付形态，不应成为所有 I2V 任务的默认输出。
- 2200 字上限、固定提示词网页结构、四段风格块等需要用真实项目测试，不能直接升为规则。

建议：

- 高优先级吸收其“资产确认、空间确认、时间确认”思想。
- 不直接吸收 `@image` 写法。
- 可把它改造成本仓库专用的“拍摄列表生成 Skill”，保持提示词层/参考层分离。

## 与现有仓库的关键对照

### 高度一致

- I2V 是连续视频事件，不是让一张图动起来。
- 单次生成一般不超过 15 秒。
- 提示词应写镜头、机位、运镜、站位、动作、声音、结束状态。
- 故事板是参考层，不是最终画面。
- 资产图应分角色、场景、道具、风格参考，各自承担明确职责。
- 不应把外部教程观点直接写入 `01_ACTIVE_RULES/`。

### 可补强现有仓库

- 在复杂镜头前加入“空间确认”步骤，尤其是双人、多角色、道具位置、战场、室内走位。
- 在拍摄前先做“资产确认表”，避免人物图、场景图、道具图和故事板职责混乱。
- 在生成提示词前先做“时间划分确认”，减少超 15 秒或过度切碎的问题。
- 将生成后的失败反馈结构化：错误类型、可能原因、下一次改法、是否需要补镜头。

### 暂不吸收

- `@image`、`@image1`、平台资产 id 等直接进入提示词正文的做法。
- 把 HTML 网页作为默认交付。
- 对所有任务强制执行完整多门确认。
- 未经测试的固定字数上限与风格块结构。

## 对“为什么使用智能体辅助 AI 短片”的方向判断

这个方向成立，因为 AI 短片的瓶颈已经从“能不能生成画面”转向“能不能稳定生产一个有故事、有视觉统一性、有镜头逻辑的片段”。这些瓶颈大多不是单次提示词能解决的，而是需要持续拆解、检查和迭代。

智能体适合承担：

- 剧本助理：扩展设定、检查冲突、压缩剧情。
- 美术助理：拆资产、生成资产提示词、检查角色/场景/道具是否齐。
- 分镜助理：把剧情拆成镜头任务。
- 场记/统筹：记录资产、空间位置、时间划分和失败原因。
- 执行导演助理：把镜头任务翻译成模型能执行的提示词。

但智能体不应替代：

- 主题选择。
- 审美判断。
- 价值观判断。
- 最终取舍。
- 对生成结果的主观评价。

最健康的方向是：人做导演，智能体做“一人剧组”的各岗位助理。Skill 不是神奇提示词，而是岗位流程说明书。

## 后续建议

1. 先把这三个 Skill 保留为外部来源，不直接安装为本仓库工作流。
2. 优先从 `deepwhite-shotlist-builder-zh-user` 中提炼“资产确认、空间确认、时间确认”三个轻量机制。
3. 后续可设计一个本仓库专用 Skill：`i2v-production-shotlist-builder`，只保留与仓库规则兼容的部分。
4. 用一个真实短剧片段做 A/B 测试：当前仓库模板 vs 加入三阶段确认后的模板。
5. 只有实测确认有效后，才考虑更新 `01_ACTIVE_RULES/` 或 `02_TEMPLATES/`。
