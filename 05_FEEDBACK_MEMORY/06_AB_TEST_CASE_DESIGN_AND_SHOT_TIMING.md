# AB Test Case Design And Shot Timing

来源：2026-06-27 用户对 V02 资产圣经 A/B 测试案例的实测反馈。

## 观察到的问题

V02 首版测试案例中，镜头 2 写成：

```text
镜头2：3秒，水壶动作特写，低机位。
画面：一名士兵从画面右侧递出旧皮水壶，李破奴戴着护腕的手猛地接住水壶，水壶皮绳晃动。
```

实测结果出现明显偏差：画面变成贴近地面的水壶和手部动作，模型把“低机位”理解成低位贴地拍摄，削弱了“士兵递出水壶、李破奴接住水壶”的手部交接关系。

同时，“接住水壶”只是瞬间动作，不足以承载 3 秒。模型会压缩该动作，把多余时长转移到后续镜头，导致镜头 4 被拉长。

另外，测试案例没有严格沿用仓库长期使用的标准格式：

```text
镜头序号：时长，景别，机位，运镜 / 摄影机路径。
镜头任务：
画面：
人物调度：
台词：
声音：
结束状态：
```

## 问题本质

这是测试案例设计错误，不是单纯的模型随机失败。

V02 本应只测试“资产圣经是否比临时资产描述更稳”，但首版案例引入了额外干扰变量：

- 机位词和动作目标冲突。
- 动作时长不匹配。
- 镜头格式不统一。
- A/B 测试变量不干净。

这会导致测试结果无法判断到底是资产圣经无效，还是测试提示词本身误导模型。

## 有效修正

- 水壶交接动作应控制在 1 秒左右。
- “接住水壶”这类手部交接，优先写：

```text
手部近景，平视，固定镜头。
```

- 如果确实需要低角度，应写清：

```text
低机位仰拍
```

而不是只写“低机位”。

- 不要让短动作承担过长时长。
- A/B 两版必须保持同一镜头结构、同一时长、同一镜头语言，只改变待测变量。
- 所有测试案例必须使用仓库标准镜头字段。

## 后续测试案例规则

以后设计 A/B 测试时，先做这 5 项检查：

1. **变量干净**：A/B 只能改变一个核心变量。
2. **动作时长匹配**：瞬间动作 1 秒左右，复杂动作才分配 3 秒以上。
3. **机位无歧义**：避免“低机位”这类可能被模型错误理解的词；必要时写“低机位仰拍”或直接去掉。
4. **格式一致**：所有版本都使用 `镜头序号、时长、景别、机位、运镜 / 摄影机路径`。
5. **时长守恒**：每个镜头时长之和必须等于目标总时长，且不要让模型自行重分配。
