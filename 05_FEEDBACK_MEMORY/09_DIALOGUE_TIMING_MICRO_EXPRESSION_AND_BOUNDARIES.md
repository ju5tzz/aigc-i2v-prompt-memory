# Dialogue Timing, Micro Expression And Positive Boundaries

来源：2026-06-30 用户对《签订合约后，皇后她赖着不走》第 71 集首版提示词的反馈。

## 观察到的问题

第 71 集首版 `71-1 凤辇出宫与京城主街欢呼` 中，一个 14 秒生成单位同时承担了出宫、上辇、主街欢呼、熟人调侃、旧宅院创伤反转和长对白。

具体问题包括：

- `【重要要求】` 写成了无意义负面提示，例如强调不要进入后续剧情。这类提示对模型执行帮助有限，反而占用注意力。
- 镜头 3、4、5 虽然包含对白和情绪转折，但缺少微表情锚点，只写了“笑着”“眼神变锐”等抽象描述。
- 多个 3 秒镜头承载了两人对白或过长台词，镜头时长明显不足。
- 一个片段内事件过多，导致提示词看似完整，实际执行时容易平均化、漏动作或压缩对白。

## 问题本质

这是提示词结构设计问题，不是单个词句问题。

I2V 提示词必须把“事件负载、对白负载、表演负载”同时纳入时长预算。镜头时长不能只按镜头数量平均分配。

## 有效修正

### 1. 有台词先做时长预算

写镜头时先粗算台词可承载量，再决定镜头秒数。

| 镜头时长 | 推荐对白量 | 适用情况 |
| --- | --- | --- |
| 1-2 秒 | 0-8 个中文字符 | 喊声、短反应、称呼、惊呼 |
| 3 秒 | 8-15 个中文字符 | 一句短台词，动作很少 |
| 4 秒 | 12-22 个中文字符 | 一句完整台词，允许一次停顿 |
| 5-6 秒 | 20-35 个中文字符 | 情绪台词、低声停顿、嘴硬转折 |
| 7 秒以上 | 35 个中文字符以上 | 长对白或内心 OS，通常应拆镜或拆生成单位 |

判断时要预留动作和反应时间。一个 3 秒镜头如果还要掀珠帘、看人、转头、表情变化，就不能再塞两个人的完整对白。

### 2. 台词过长时优先拆分

可选处理：

- 拆成两个镜头，一句台词对应一个表演重点。
- 一半改成画外音，画面拍反应或动作。
- 拆成两个生成单位，不强行塞进 15 秒。

不要为了塞进短镜头删减台词。台词本身是剧本资产，时长不足时应拆镜续接后半句。

输出镜头时长时，只允许整数或 `.5`，按最接近的 `0.5 秒` 四舍五入。

### 3. 近景对白必须带表情锚点

中近景、近景、特写中，只写“镇定、笑着、眼神变锐”不够。应转成可执行部位和动态变化：

```text
表情变化：苏瑾原本带着市井式轻笑；看见旧宅院时，嘴角停住半秒，眼尾微微压低，握住珠帘的手指收紧；随即重新勾起嘴角，抬眼看向前方。
```

### 4. 重要要求改成正向生成边界

不要把重要要求写成一串“不要生成什么”。更稳写法是：

```text
【生成边界】
本片段结尾停在凤辇驶离旧宅院，苏瑾重新看向主街前方。百姓只作为两侧群体欢呼和声音背景，视觉焦点始终落在苏瑾与柳娘。
```

## 后续规则

以后从剧本批量生成标准分镜头提示词时，输出前必须检查：

1. 当前生成单位是否只承载一个连续事件。
2. 有台词的镜头是否通过对白字数和镜头时长检查。
3. 情绪转折近景是否写了 2-4 个微表情锚点。
4. 重要要求是否是正向边界，而不是无意义负面项。
5. 如果 15 秒内放不下，应主动拆成多个生成单位。
