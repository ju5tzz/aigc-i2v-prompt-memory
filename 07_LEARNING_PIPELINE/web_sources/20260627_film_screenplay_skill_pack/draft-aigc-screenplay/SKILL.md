# Draft AIGC Screenplay

## 定位与职责边界（Boundary）

把已锁定的故事核心、人物和分场扩写为正式剧本，或依据用户已采纳的问题单执行结构修改。

负责：

- 标准影视剧本和文学化处理稿；
- 分场扩写、续写、压缩和局部重写；
- 执行已采纳的诊断修改；
- 保持资产 ID、角色状态和场次因果；
- 更新正式剧本、连续性变化和版本记录。

不负责：

- 重新设计故事前提、主题、结局或主要人物弧光；
- 独立判定整剧哪里有问题；
- 全面台词精修；
- 最终视频提示词和逐镜分镜。

发现结构问题时交给 `diagnose-aigc-screenplay`；发现上游设定冲突时退回 `develop-aigc-screenplay`。

## 共享项目状态包（Shared Project State）

输入应包含 `develop-aigc-screenplay` 的 `project-state-template` 对应内容。

本 Skill 可直接更新：

- 正式剧本最新版；
- 连续性状态账本中的本次变化；
- 已采纳修改清单的执行状态；
- 版本变更记录；
- 剧本结构阶段状态。

人物圣经、主题、结局、资产规则和分场表只读。需要修改时提交变更请求。

## 阶段门禁（Gate）

### 完整初稿

必须满足：

- 故事核心：已锁定；
- 人物设定：已锁定；
- 分场表：已锁定。

未满足时，只允许试写指定场次，并明确标记“非锁定试写”。

### 结构修改稿

必须提供用户确认的“已采纳修改清单”。不得把诊断 Skill 的全部建议默认视为已采纳。

### 路由条件

- 需要判断问题而非执行修改：使用 `diagnose-aigc-screenplay`；
- 结构已锁定、只优化对白：使用 `polish-screenplay-dialogue`；
- 修改主题、结局或主要人物弧光：退回 `develop-aigc-screenplay`。

## 写作模式

### 标准影视剧本

适合正式分场、真人制作和下游分镜：

```text
SC001　内／外景　地点　时间

可见、可听的环境与人物状态。

角色名
对白

动作与结果。
```

### 文学化处理稿

用于开发氛围、情绪和连续动作，允许有限心理解释，但必须与正式剧本事实一致。

它不是视频模型提示词，不使用关键词堆砌，也不替代分镜。

## 写作流程

完整规则读取 `references/drafting-workflow.md`。

1. 校验项目状态与本轮范围；
2. 读取锁定的节拍、场次、人物和资产；
3. 建立场次进入状态；
4. 写可见、可听、可执行的剧本；
5. 记录离场状态和下一场因果；
6. 更新连续性与新增资产疑点；
7. 输出写作交接摘要。

## AIGC 写作规则

- 抽象情绪转化为目光、呼吸、姿态、距离、动作和停顿；
- 复杂动作按“意图—发力—结果”组织；
- 明确谁接触什么、动作方向和物理结果；
- 不在单个潜在生成单元塞入过多连续动作；
- 关键对白不跨不自然的生成切分；
- 不滥用焦段、运镜和剪辑术语；
- 不为了降低风险擅自删除核心戏剧功能；
- 新增关键资产或状态必须建档或提出变更请求。

## 修改流程

读取 `references/revision-workflow.md`。

修改时：

- 只改已采纳问题涉及的场次；
- 保留未受影响内容；
- 列出受影响的后续场次、资产和状态；
- 若修改导致新的结构问题，停止扩散并请求重新诊断；
- 每次输出标明旧版本、新版本和修改 ID。

### 已锁定故事保护（Locked Story Protection）

不得改变已锁定的主题、结局或人物弧光。用户要求改变时，明确退回主控重新锁定，而不是“顺手改掉”。

## 台词处理边界

初稿阶段只保证：

- 对白传递必要信息；
- 符合人物基本身份；
- 不明显 OOC；
- 可朗读、可表演。

不在结构仍会变化时进行逐句精修。结构锁定后交给 `polish-screenplay-dialogue`。

## 输出

使用 `assets/draft-handoff-template.txt` 交付：

- 剧本版本和范围；
- 正文；
- 连续性变化；
- 新增或变更资产；
- 未解决冲突；
- 建议的下一步路由。

## 常见错误

- 发现故事不合理后直接重写结局；
- 把未采纳的诊断意见全部执行；
- 扩写场景时新增关键人物却不报备；
- 用文学化描述代替物理动作因果；
- 写完初稿后立即全面磨台词；
- 修改一场戏却不检查后续状态。
