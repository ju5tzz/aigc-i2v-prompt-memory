# AB Test Case Dramatic Contrast

来源：2026-06-27 用户对 Skill 包整合前 A/B 测试案例的复核反馈。

## 观察到的问题

当前 A/B 测试案例虽然保留了测试表和变量方向，但案例本身全部作废。

根本原因不是某个镜头写错，而是取材策略错误：案例从一个已有但低冲突、低戏剧性的旧剧本中截取片段，导致很多测试项无法充分拉开 A/B 差异。

典型问题：

- 低冲突场景无法验证“环境参与”是否增强戏剧表达。
- 低戏剧张力场景无法验证“连续性信息状态”是否改变表演和镜头重点。
- 普通递水、跪谢、询问等动作太弱，无法证明资产圣经、时间预算、对白检查等机制的真实价值。
- 测试变成形式主义的流水线工作，看似完成了 A/B，但结论无法支撑 Skill 包结构决策。

## 核心修正

A/B 测试案例不应被原剧本内容限制。

测试案例应服务于变量验证，而不是忠实复刻旧剧本。为了更戏剧性地体现差异，可以主动重构人物关系和情境。例如：

- 让李校尉变成叛徒。
- 让萧烈变成奸诈或隐藏动机的人。
- 让男女主角、军医、士兵、少年等角色承担更强冲突功能。
- 让同一镜头里存在误会、背叛、诱骗、反转、秘密、伏笔、危险倒计时。

只要测试目标是验证规则或 Skill 模块，案例就可以是专门设计的“压力测试场景”，不需要被原项目剧情锁死。

## 后续 A/B 案例设计规则

以后设计 A/B 测试案例，必须先完成以下检查：

1. **变量可显影**  
   场景必须能明显放大 A/B 差异。若 A/B 在这个场景中看不出差异，场景不合格。

2. **冲突足够强**  
   优先使用背叛、误会、身份反转、隐藏动机、危险倒计时、重要道具争夺、压迫审讯、情感决裂等高冲突场景。

3. **角色关系有张力**  
   不要只使用“忠臣递水”“军医解释”这类低冲突关系。测试可以临时改变角色立场，让角色之间形成对抗。

4. **变量单一但场景强烈**  
   A/B 仍然只能改变一个核心变量，但场景本身可以足够戏剧化。

5. **测试服务结论**  
   每个案例都要能回答：如果 B 更好，是否足以支持该机制进入最终 Skill 包？

6. **不为旧剧本牺牲代表性**  
   旧剧本只能提供素材，不是测试边界。为了验证机制，可以重写场景前提、角色动机和冲突。
