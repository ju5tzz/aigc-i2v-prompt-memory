# I2V 提示词工作流

使用本技能为用户的 Seedance / I2V 短剧工作流生成“提示词正文层”，并把外部创作者经验转化为可验证假设，而不是直接照搬。

## 核心规则

1. 只输出提示词正文层。不要在正式提示词中写 `@Image`、`@Video`、`@Audio`、`{{Portrait N}}`、平台资产编号或猜测性的参考绑定。
2. 除非用户明确要求，不输出参考对象职责表。用户会在平台内自行处理全能参考素材。
3. 提示词写给模型执行，不是写给人阅读。只保留模型能转化为画面、动作、声音、空间、镜头行为或时间节奏的信息。
4. 外部教程、帖子、技能或创作者经验不能直接升格为规则。先拆成变量，再转化为可测试假设。
5. 只有用户在真实 I2V 工作中验证有效的经验，才能进入稳定规则。

## 提示词写作流程

1. 先判断任务类型：
   - 剧本转提示词
   - 提示词评审
   - 故事板转提示词
   - 竖屏短剧改写
   - 长镜头 / 一镜到底
   - 外部经验筛选

2. 如果正在 `D:\Codex\aigc-i2v-prompt-memory` 仓库内工作，先读取相关记忆：
   - `00_PROJECT_BRIEF.md`
   - `01_ACTIVE_RULES/`
   - `02_TEMPLATES/`
   - 相关 `05_FEEDBACK_MEMORY/`
   - 外部资料任务读取相关 `07_LEARNING_PIPELINE/`

3. 套用标准模板前，先做这些判断：
   - 当前生成片段只覆盖哪一个连续事件？
   - 是否需要“当前片段前置信息”？只有当画面外信息会改变本片段的表演、语气、犹豫、隐瞒、崩溃或动作选择时才加入。
   - 是否需要“环境参与”？只在关键戏剧节点使用，并绑定到具体动作、脸部、声音、光线、道具或停顿。
   - 是否需要脸部近景或反应特写？如果要表现微表情、心虚、察觉、蛊惑、压抑哭泣或隐藏意图，应加入近景 / 特写。
   - 是否需要“表情层”？只有当镜头承担情绪变化、关系反转、隐瞒、诱导、杀意、羞耻、恐惧、压抑或高光对峙时才展开；普通动作和过场镜头不要硬套。
   - 镜头数量是否能承载当前情绪和动作负载？不要习惯性强行写成三个镜头。
   - 每个动作是否匹配所分配的时长？瞬间动作应短，发现、反应、对白和情绪转折可以更长。
   - 每个有台词的镜头是否已经参考 `references/dialogue-timing.md` 做过对白时长预算？如果对白字数超过镜头可承载范围，不要删减台词，应拆成两个或多个镜头续接后半部分，或拆成多个生成单位。
   - 是否需要短插镜？对话另一方冷脸、旁观者反应、手部动作、道具或场景细节通常只占 `0.5-1 秒`，少数情绪迟疑可到 `1.5 秒`。短插镜用于丰富节奏、承接剪辑和强化戏剧点，不用于承载长信息。
   - 输出镜头秒数时，小数点后一位只允许 `0` 或 `5`，按最接近的 0.5 秒四舍五入。
   - 是否需要故事板支持？只有复杂空间、明确摄影机路径、战争 / 动作调度、机械奇观或强连续性时优先考虑故事板。

4. 按场景、时间跳转、情绪转折、主体变化或悬念点，把剧本拆成生成单位。单个短想法可以视为一个生成单位。

5. 判断每个生成单位适合多镜头还是长镜头：
   - 信息变化、反应重要、对白需要节奏、短剧需要剪切时，用多镜头。
   - 连续动作、空间穿行、沉浸式跟拍或压迫式调度时，可以用长镜头。

6. 每个镜头至少写清：
   - 时长
   - 景别
   - 机位 / 角度
   - 运镜 / 摄影机路径
   - 可见动作
   - 台词
   - 表情 / 表情变化（按需）
   - 当前声音 / 音效
   - 结束状态

7. 提示词中可以保留人物名，用于剧情调度和台词归属；除非用户明确要求或没有参考资产，不要重复写完整人物外貌。

8. 9:16 竖屏短剧不要连续使用中景、平视、固定、轻微推近。根据戏剧节点使用反应切镜、物件特写、脸部特写、低机位、主观视角、前景遮挡、画外音或突然推近。

9. 输出前清理提示词：删除只给人类看的解释、重复信息、冲突指令、过度全局化背景、无意义负面提示，以及与当前片段无关的信息。重要要求只保留正向生成边界、主体优先级和最终停点。

10. 只要提示词含有台词，就必须读取并应用 `references/dialogue-timing.md`：先按台词类型估算语速、气口和反应镜头，再决定镜头时长。台词过长时用拆镜承接，不用删词压缩。

## 短插镜与长对白拆分

短插镜是竖屏短剧的节奏工具，不是拖慢镜头的理由。它适合插入在长对白、情绪转折、观众需要接收信息、剪辑需要换气的位置。

- 常用短插镜包括：对话另一方的冷脸或忍耐反应、旁观者倒吸气或互看、手指收紧、衣袖摩擦、契约/印章/茶杯/刀柄等道具细节、窗外雷光或烛火跳动。
- 短插镜通常控制在 `0.5-1 秒`。只表现一个清晰反应或一个道具状态，不写复杂动作链。
- 少数情绪迟疑、落泪前停顿、关键道具被看清，可以放到 `1.5 秒`；超过 `2 秒` 时必须确认它是否已经变成独立表演镜头。
- 长对白不要塞进一个固定中景。应按语义折点、情绪折点或关系反转拆成 `2-3 个镜头`：说话人近景承接前半句，听者反应或道具短插镜承接后半句，必要时把后半句处理成画外音。
- 短插镜必须服务当前剧情触发点。不要为了“丰富镜头”机械插入空镜，否则会抢走表演重点。

## 人物表情层

写人物表演时，先判断是否需要表情层，再决定写到多细。表情层是按需启用的镜头字段，不是每个镜头的固定模板。

### 表情层判断

- 抽象情绪必须翻译成可见脸部部位。不要只写“愤怒、害怕、嘲讽、难过”，要转成眉毛、眼神、嘴部、面部肌肉、呼吸或身体反应。
- 表情必须绑定动作、台词和当前剧情触发点。表情不是装饰，要说明角色正在做什么、刚听到或看到什么、为什么这一秒泄露这种情绪。
- 景别决定表情颗粒度。远景 / 全景写大动作、姿态、后退、握拳、停顿；中景 / 中近景写眼神方向、眉头、嘴角、呼吸；近景 / 特写才写瞳孔、眼尾、唇线、咬肌、面部细纹、泪光。
- 微表情应写成短暂动态过程：初始表情、触发事件、细微变化、立刻恢复。关键词是细微、短暂、不易察觉，不是夸张。
- 多人场景需要表情主次。主角表情精细突出，对手表情形成反差，配角符合人设但简化处理，不抢主体。
- 表情提示不应每镜头硬套四部位。只有近景、特写、反应镜头、情绪转折、高光对峙才展开；远景、动作调度、普通过场只写整体情绪或身体反应。

### 单人物表情写法

```text
表情：眉毛...；眼神...；嘴部...；面部肌肉...；整体情绪...
```

只选择当前镜头最关键的 2-4 个表演锚点。不要把同一情绪的全部细节堆进一个镜头。

### 微表情写法

```text
表情变化：人物原本保持...；听到/看到...时，眼神/眉毛/嘴角微微...；随即恢复...；变化极快，不易察觉。
```

微表情最适合隐瞒真实动机、谎言被戳中、关系反转、战前对峙、爱恨压抑、恐惧或羞耻不能直接外露的瞬间。

### 多人表情写法

```text
表情主次：主角表情精细突出；对手表情形成反差；配角符合人设但简化处理，不抢主体。
```

多人镜头不要只让说话者有表情，也不要让所有人同等详细。主角承担视觉焦点，对手承担情绪反差，配角只提供场面可信度。

## 外部经验筛选

当用户提供外部教程、帖子、视频、技能或创作者工作流时：

1. 提取每条可执行主张。
2. 把每条主张标记为：
   - 大概率兼容
   - 与当前规则冲突
   - 需要直接测试
   - 当前无关
3. 保留冲突，不要过早调和。
4. 在记忆仓库工作时，把有用但未验证的主张保存到学习管线，标记为待验证经验。
5. 除非用户明确说明该经验已经在真实项目中验证有效，不要修改 `01_ACTIVE_RULES/`。

处理外部技能、教程、社区经验时，读取 `references/external-triage.md`。

## 台词时长提示

处理带台词的镜头、对白戏、告白戏、嘴炮戏、冲突对峙、内心独白或画外音时，必须读取 `references/dialogue-timing.md`。

应用顺序：

1. 统计每句台词字数，不计算说话人姓名和标点。
2. 判断台词类型：嘴炮、日常、对峙、告白、金句、内心独白 / 画外音。
3. 按公式估算 `台词字数 / 语速系数 + 气口 + 反应镜头`。
4. 将时长四舍五入到最接近的 0.5 秒。
5. 如果单镜头太长或超过当前生成单位承载范围，保留台词原文，拆成两个或多个镜头续接。

## 长镜头提示

处理一镜到底、连续动作或空间穿行时，优先保证摄影机连续性，而不是堆动作数量：

- 把摄影机写成一个正在移动的拍摄者。
- 把动作绑定到真实场景物件。
- 摄影机路径通常要比动作编排写得更清楚。
- 写清有动机的光源及其方向。
- 长负面提示词只作为测试假设，不作为默认写法。

写长镜头 / 一镜到底时，读取 `references/long-take.md`。

## 可保留的外部模式

从外部提示词技能中可以保留这些思想：

- 一个生成单位应有清楚的场景 / 任务边界。
- 道具如果影响连续性，就要写清状态。
- 每个镜头要有景别、构图、机位、运动和物理动作。
- 先判断多镜头还是长镜头，不要默认套一种格式。

不要直接保留这些做法：

- 在提示词正文中写 `{{Portrait N}}`、`@Image` 或平台资产绑定。
- 参考资产已经承担身份时，仍反复写完整人物外貌。
- 无测试理由地堆叠电影镜头、镜头型号、胶片风格词。
- 默认使用长负面词列表。

需要标准结构时，读取 `references/prompt-structure.md`。
