# Model-Facing Prompt And Dialogue Punctuation

来源：用户实测反馈。

## 观察到的问题

I2V 提示词容易被写成给人看的分镜说明，而不是给模型执行的生成指令。

典型问题包括：

- 把人物名误认为模型已经天然理解的视觉概念。
- 声音字段写成抽象表演说明，例如“声音压着激动”。
- 结束状态重复画面段落，或期待模型精确遵循过细的抽象指令。
- 忽略台词标点对语气、停顿和情绪的影响。

## 可能原因

模型不天然知道项目内人物名对应的视觉形象。

在全能参考模式下，人物名最终需要由用户在平台参考层中手动绑定到角色设定图，才具有明确视觉指向。

但当前 Codex 工作流只负责提示词层，不负责参考层。Codex 输出的提示词应保持为纯提示正文，不直接包含 `@` 标签，也不猜测资产映射。

同时，模型对可见动作、空间位置、台词文本、标点和可生成声音的响应，通常强于对抽象声音描述和总结式结束状态的响应。

## 有效修正

- 把“提示词是给模型读的”作为第一判断原则。
- 人物首次出现和关键动作处保留清晰的人物名、动作、位置和视线关系。
- 把 `@` 资产绑定留给用户在 I2V 平台中手动完成。
- 把关键结束状态写进画面和人物调度，而不是只放在“结束状态”字段。
- 台词保留精确标点，用 `……`、`！`、`？！`、`——` 等控制停顿和情绪变化。
- 声音字段只写当前片段真实可生成的声音，例如对白、呼吸、衣料摩擦、环境音。

## 适用范围

- Seedance / I2V 全能参考模式。
- 多角色对话。
- 需要口型、语气、情绪递进的短剧镜头。
- 角色资产已经准备好，并由用户在平台参考层手动绑定的项目。

## 不适用范围

- 没有角色参考资产、只能纯文本生成的任务。
- 不需要人物一致性的抽象视觉片段。
- 后期配音和 I2V 画面生成完全分离的流程。

## 当前工作流边界

Codex 输出：

```text
小明对着老师鞠了一躬。
```

用户在平台中手动补充参考层：

```text
小明@图一 对着老师@图二 鞠了一躬。
```

因此，Codex 不应把参考绑定写入正式提示词。
